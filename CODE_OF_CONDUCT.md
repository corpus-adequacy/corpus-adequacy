# Code of Conduct

This project adopts the [Contributor Covenant, version 3.0](https://www.contributor-covenant.org/version/3/0/code_of_conduct/)
as its code of conduct. It applies in this repository, its issues, pull requests and Discussions,
and wherever someone represents the project.

The rest of this file covers what the Covenant leaves to each project: where to report, who reads
a report, and what happens after.

## Reporting

Report a conduct concern privately to: **CONDUCT_ROUTE_PENDING**

This route is for conduct only. A security vulnerability goes through the private route in
[SECURITY.md](SECURITY.md), and neither route stands in for the other. Please do not report a
conduct concern in a public issue, pull request or Discussion.

## Who reads a report

Corpus Adequacy has one maintainer, and the maintainer is the only reader of this route. Two
things follow from that, and they are stated here rather than left for a reporter to discover:

- **A report about the maintainer has no independent reader inside the project.** Report it to
  GitHub instead, through the report option on the content or account concerned, or through
  [GitHub's abuse reporting](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam).
- **A report waits while the maintainer is unavailable.** Nobody else reads the route.

The route belongs to the project rather than to anyone's private inbox, so it can be handed to a
successor maintainer without changing the address published here. Recovery access to it is kept
outside this repository.

## What happens after a report

1. The maintainer reads the report and, when a reply address is given, confirms it was received.
   No response time is promised.
2. The report stays private. Its details are shared only with the people it concerns, only as far
   as is needed to act on it, and never published without the reporter's consent.
3. A response follows the Covenant's *Addressing and Repairing Harm* section, in proportion to what
   happened.
4. The maintainer keeps a private record of the outcome, not of the report's contents.
5. A reporter who is not satisfied with the response can take it to GitHub as described above.

## What this does not do

It does not make the community safe by itself, and it promises no response or resolution time. It
is not a channel for vulnerability reports, and the vulnerability route is not a channel for
conduct.
